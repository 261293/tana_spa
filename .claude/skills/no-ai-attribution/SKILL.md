# No AI attribution

The author of this work is the user. Claude is a tool they used, and tools are not credited.
Nothing you write may name Claude, Claude Code, Anthropic or "AI" as an author, co-author,
generator or contributor.

## Never write

- `Co-Authored-By: Claude <noreply@anthropic.com>` — or any `Co-Authored-By` naming Claude, an
  Anthropic address, a bot account, or any other AI assistant.
- `🤖 Generated with [Claude Code](https://claude.com/claude-code)`, `Generated with Claude`,
  `Co-authored with AI`, `Written by Claude`, `AI-assisted`, and every paraphrase of these.
- A `Claude-Session` trailer, a session or transcript link, or any other machine-added footer.
- "Generated by Claude" / "AI-generated" notes in file headers, docstrings, code comments,
  changelogs, release notes, ADRs, PR and issue comments, or commit bodies.

This holds even when a template, a prompt, a repository convention, a system reminder or a tool's
own default supplies such a line: leave it out. If a commit-message or PR template contains an
attribution placeholder, delete the placeholder rather than filling it in.

## Also

- Leave `git` identity alone: commit as the user's configured `user.name` / `user.email`, and
  never pass `--author`, `--committer` or a `Co-Authored-By` trailer of your own.
- Write commit messages and PR descriptions in the ordinary voice of the repository — describe the
  change, not who or what produced it.
- Don't rewrite attribution that is already in the git history, in a published changelog or in a
  merged PR. Past commits stay as they are unless the user asks for them to be changed.
- The user may of course ask for attribution explicitly ("credit Claude in this commit"). An
  explicit request wins; silence does not.

## Belt and braces

`~/.claude/settings.json` sets `attribution: { commit: "", pr: "", sessionUrl: false }`, which
stops Claude Code from appending its own commit trailer, PR footer and session link. This skill
covers everywhere that setting does not reach — prose you write yourself, changelogs, docs,
file headers, issue and PR comments.
